# 📰 News Digest Bot — Инструкция

Автоматический сбор и рассылка актуальных IT-новостей в Telegram — и бот, который
отвечает на команды, учится на ваших 👍/👎 и не ждёт утра, если случилось что-то
срочное.

Работает на Python 3.8+, **без внешних зависимостей**, хранит всё в `~/.newsdigest/`.

---

## 🚀 Быстрый старт

### 1. Первичная настройка

```bash
python3 digest.py setup
```

Интерактивный мастер попросит:
- **Токен Telegram-бота** (от [@BotFather](https://t.me/BotFather))
- **Chat ID** (определит автоматически, если вы напишете боту сообщение)
- **API ключ DeepSeek** (platform.deepseek.com)
- **Тему** новостей: `ai` | `crypto` | `cybersec` | `custom`
- **Время отправки** (ваше локальное время, например 09:00)
- **Часовой пояс** (например `Europe/Riga`, `Europe/Moscow`)
- **Кол-во новостей** в выпуске (5–10)

Все данные сохранятся в `~/.newsdigest/env` с правами `600`.

### 2. Проверка подключений

```bash
python3 digest.py doctor
```

Проверяет:
- ✅ Telegram-бот и chat_id
- ✅ DeepSeek API и баланс
- ✅ Базу данных
- ✅ Часовой пояс

### 3. Тестовый прогон

```bash
python3 digest.py run --dry-run
```

Собирает и показывает дайджест в терминале, но **не отправляет** в Telegram.
Видно примерную стоимость запроса к LLM.

### 4. Запуск демона

```bash
python3 digest.py daemon
```

Фоновый процесс:
- Собирает новости каждые 4 часа (настраивается: `ND_COLLECT_EVERY`)
- Отправляет дайджест ровно в `send_at` (если за день ещё не отправлял)
- **Слушает команды в чате** и отвечает на них
- **Проверяет срочные новости** после каждого сбора
- Автоматически перезагружается при ошибках

**Как поднять на VPS:**

```bash
# Локально: сгенерировать unit-файл для systemd
python3 digest.py service > newsdigest.service

# На VPS (с sudo):
sudo cp newsdigest.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now newsdigest

# Проверить статус:
systemctl status newsdigest
```

Или проще (без root):
```bash
nohup python3 digest.py daemon --log-file >/dev/null 2>&1 &
```

> На VPS нужен весь каталог проекта (файл `digest.py` **и** папка `newsdigest/`),
> а не один файл. Команды запуска не изменились.

## 💬 Команды в чате

Демон держит открытым long-poll к Telegram, поэтому бот отвечает сразу. Тяжёлые
задачи (сбор, запросы к модели) уходят в фоновую нить — пока идёт прогон, бот
продолжает разговаривать.

| Команда | Что делает |
|---------|-----------|
| `/help` | Список команд |
| `/digest` | Собрать и прислать выпуск прямо сейчас |
| `/more [N]` | Ещё новости, которые не влезли в выпуск (бесплатно) |
| `/breaking` | Проверить, нет ли чего-то срочного |
| `/saved` | Закладки (`/saved clear` — очистить) |
| `/taste` | Что бот выучил про ваши вкусы |
| `/status` | Расписание, расход, проблемные источники |
| `/feeds` | Проверить каждый источник по одному |
| `/settings` | Все настройки с текущими значениями |
| `/set имя значение` | Изменить настройку |
| `/feed`, `/keywords` | Править источники и ключевые слова (владелец) |
| `/subs` | Подписчики (владелец) |
| `/pause`, `/resume` | Приостановить и вернуть свои выпуски |
| `/stop` | Отписаться |

Отключить приём команд: `ND_LISTEN=0` — останется поведение версии 2.0.

> Команды `setup` и `chatid` определяют chat_id через `getUpdates`. Если демон
> запущен, Telegram ответит одному из них `409 Conflict` — остановите демон на
> время настройки.

## 👍 Обратная связь: бот подстраивается

Под каждой новостью в выпуске три кнопки: **👍**, **👎** и **🔖** (в закладки).

Реакции идут в дело двумя путями:

1. **Прескоринг.** Источники и категории, которые вам нравятся, поднимаются в
   шорт-листе и чаще доезжают до модели. Вклад ограничен `feedback_weight`
   (по умолчанию 0.25), а сглаживание не даёт одной случайной реакции
   перевернуть картину.
2. **Промпт.** Модели показывают несколько недавних «зашло / не зашло» —
   с оговоркой, что по-настоящему важное событие публикуется в любом случае.

`/taste` показывает накопленную статистику. Эффект заметен примерно через неделю.

```bash
export ND_FEEDBACK=0          # убрать кнопки совсем
export ND_FEEDBACK_WEIGHT=0   # оставить кнопки, но не влиять на отбор
```

## ⚡ Срочные новости

Событие, о котором за пару часов написали сразу несколько первоисточников, не
ждёт девяти утра. Проверка идёт после каждого сбора и требует **трёх**
независимых подтверждений:

1. **Консенсус** — `breaking_min_sources` разных сайтов за `breaking_window_h`,
   и хотя бы один из них tier-1. Либо новость в одиночку набрала ~270+ баллов
   на Hacker News.
2. **Оценка модели** не ниже `breaking_min_score` (8.0 против обычных 5.5).
   Если модель недоступна, срочное **не** отправляется: без оценки слишком легко
   разбудить человека ради пересказа чужой новости.
3. **Приличия** — тихие часы, лимит в сутки, пауза рассылки.

Отправленное сразу попадает в историю, поэтому в утреннем выпуске не повторится.

```bash
export ND_BREAKING=0                  # выключить совсем
export ND_BREAKING_QUIET=23:00-08:00  # часы тишины (или «нет»)
```

## 👥 Несколько подписчиков

Бот умеет обслуживать несколько чатов. У каждого своя история (дедупликация не
общая), своя тема, своё время и свои лимиты.

- Новый чат пишет `/start` → попадает в ожидание, владелец получает кнопки
  «✅ Пустить» / «🚫 Нет».
- `ND_SIGNUP=open` подписывает сразу, `ND_SIGNUP=off` возвращает поведение
  строго личного бота.
- Владелец (`TELEGRAM_CHAT_ID`) меняет настройки **для всех**, подписчик — только
  свои: `topic`, `time`, `tz`, `language`, `max`, `score`, `silent`.
- `/subs` — список, `/subs add <chat_id>`, `/subs rm <chat_id>`.

**Про расход:** новости собираются один раз на всех, а вот ранжирование и
карточки — свои для каждого подписчика. Расход на модель растёт примерно
пропорционально числу подписчиков.

## ⚙️ Настройка

Настройки живут в трёх местах, от простого к сложному:

1. **`/set` в чате** — самое быстрое, применяется на лету и переживает
   перезапуск.
2. **Файл `~/.newsdigest/env`** — то же самое, но руками.
3. **`newsdigest/config.py`** — значения по умолчанию и то, чего нет в `/set`.

```bash
export ND_TOPIC=ai                    # Тема: ai | crypto | cybersec | custom
export ND_SEND_AT=09:00               # Время отправки
export ND_TZ=Europe/Moscow            # Часовой пояс (с переходом на летнее время)
export ND_COLLECT_EVERY=4             # Сбор каждые N часов
export ND_MIN_ITEMS=5                 # Минимум новостей в выпуске
export ND_MAX_ITEMS=8                 # Максимум новостей в выпуске
export ND_MIN_SCORE=5.5               # Порог важности (1–10)
export ND_LANGUAGE=русский            # Язык дайджеста
export ND_SILENT=1                    # Отправлять без звука
export ND_LISTEN=1                    # Отвечать на команды в чате
export ND_SIGNUP=ask                  # ask | open | off — как пускать новые чаты
export ND_FEEDBACK=1                  # Кнопки 👍/👎/🔖
export ND_FEEDBACK_WEIGHT=0.25        # Насколько реакции двигают отбор (0–1)
export ND_BREAKING=1                  # Срочные новости вне расписания
export ND_BREAKING_QUIET=23:00-08:00  # Часы тишины для срочного
export TELEGRAM_BOT_TOKEN=...         # Токен бота
export TELEGRAM_CHAT_ID=...           # Chat ID владельца
export DEEPSEEK_API_KEY=...           # API ключ DeepSeek
```

## 🧩 Расширение и кастомизация

### Добавление источника — без правки кода

Прямо в чате:

```
/feed add https://blog.rust-lang.org/feed.xml 1 labs
/feed rm techcrunch
/feed list
/keywords add mlops vector
```

Новый источник сразу проверяется загрузкой: если фид не отвечает, он не
добавится, и вы узнаете об этом сейчас, а не через сутки.

Правки лежат в `~/.newsdigest/profiles.json` — его можно писать и руками:

```json
{
  "ai": {
    "feeds": [["my-blog", "https://example.com/rss", 1, "labs"]],
    "remove_feeds": ["theverge"],
    "keywords": ["mlops"]
  },
  "гаджеты": {
    "persona": "читатель, которому интересно железо и его цены",
    "keywords": ["laptop", "gpu"],
    "feeds": [["notebookcheck", "https://www.notebookcheck-ru.com/rss.xml", 2, "media"]]
  }
}
```

Для встроенной темы правка **дополняет** её (а `remove_feeds` убирает лишнее),
поэтому обновление кода не затирает ваши источники. Новая тема описывается
целиком. Сломанный JSON не роняет бота: ошибка уходит в лог, работа
продолжается на встроенных темах.

Запись фида понимается в трёх видах: `"https://..."`, `["id", "url", tier,
"категория"]` или `{"url": "...", "tier": 1, "category": "labs"}`.

- **tier:** 1 = первоисточник, 2 = профильное СМИ, 3 = агрегатор/форум.
- **категории:** labs, research, opensource, media, community, business, policy, other.

### Замена LLM (например, на OpenAI)

В `newsdigest/config.py`:

```python
"llm_base":      "https://api.openai.com/v1",
"model_rank":    "gpt-4o-mini",
"model_summary": "gpt-4o-mini",
```

Ключ читается из `DEEPSEEK_API_KEY` — либо положите туда чужой ключ, либо
поправьте `newsdigest/llm.py`. Протокол ожидается OpenAI-совместимый
(`/chat/completions` с `response_format: json_object`).

### Изменение веса критериев ранжирования

В `newsdigest/config.py`, секция `WEIGHTS`:

```python
WEIGHTS = {
    "source_tier":   0.30,   # Первоисточник vs пересказ (↑ = доверие источникам)
    "corroboration": 0.25,   # Сколько сайтов пишут об этом (↑ = ищем консенсус)
    "social":        0.20,   # Баллы Hacker News (↑ = сообщество важнее)
    "freshness":     0.25,   # Свежесть новости (↑ = только горячее)
}
```

### Чистка базы и логов

```bash
# Удалить материалы старше 10 дней
sqlite3 ~/.newsdigest/digest.db "DELETE FROM items WHERE fetched_at < datetime('now', '-10 days');"

# Очистить всю базу (⚠️ потеряются история, реакции и дедупликация!)
rm ~/.newsdigest/digest.db

# Очистить логи
rm ~/.newsdigest/digest.log*
```

## 🛠 Troubleshooting

### Бот не отправляет новости

1. `python3 digest.py doctor`
2. `tail -50 ~/.newsdigest/digest.log | grep -i error`
3. `python3 digest.py status` — смотрите «Проблемные источники»

### Бот не отвечает на команды

- Проверьте, что демон запущен: `ps aux | grep "digest.py daemon"`
- В логе должна быть строка «Слушаю команды в Telegram»
- `ND_LISTEN` не должен быть `0`
- Два процесса-демона одновременно работать не могут: Telegram отдаст
  `409 Conflict` одному из них

### Неправильное время отправки

- Проверьте часовой пояс: `python3 digest.py doctor`
- Пересохраните: `/set tz Europe/Riga` или `ND_TZ`
- Проверьте время на VPS: `timedatectl`

### Высокие расходы на DeepSeek

```bash
python3 digest.py status  # Видно расход за неделю
```

Чтобы снизить:
- Уменьшите `ND_MAX_ITEMS`
- Снизьте `llm_candidates` в `config.py`
- Уменьшите число подписчиков: каждый — свой запрос к модели
- Выключите срочные: `ND_BREAKING=0`

### Исчезли старые новости

Нормально — удаляются через 10 дней (`keep_items_days`). История отправленного
живёт 60 дней (`keep_sent_days`) и нужна для защиты от повторов.

## 📊 Архитектура (для разработчиков)

```
digest.py                 ← точка входа, тонкая обёртка
newsdigest/
├── config.py             ← CFG, WEIGHTS, окружение, часовой пояс, логи
├── profiles.py           ← встроенные темы
├── userprofiles.py       ← ~/.newsdigest/profiles.json поверх встроенных
├── settings.py           ← что можно менять из чата и как это проверяется
├── net.py                ← HTTP: один opener, gzip, 308-редиректы
├── feedparse.py          ← разбор RSS/Atom и дат
├── textutil.py           ← канонизация ссылок, сигнатуры, похожесть
├── storage.py            ← SQLite: схема, миграции
├── subscribers.py        ← подписчики, личные настройки, расписание
├── sources.py            ← сбор из фидов и Hacker News
├── rank.py               ← кластеризация, прескоринг, отбор
├── feedback.py           ← реакции и их влияние на отбор
├── llm.py                ← ранжирование и карточки
├── telegram.py           ← транспорт Bot API
├── render.py             ← сборка текста и кнопок
├── pipeline.py           ← конвейер выпуска
├── breaking.py           ← срочные новости
├── bot.py                ← команды и нажатия кнопок
├── daemon.py             ← расписание + long-poll
└── cli.py                ← аргументы командной строки
tests/                    ← смоук-тесты, сеть не трогают
```

**Три нити в демоне:**
- главная — long-poll `getUpdates`, отвечает на команды;
- `scheduler` — раз в минуту смотрит, не пора ли собрать или отправить;
- `worker` — выполняет тяжёлое по одной задаче за раз.

**Данные:**
- `~/.newsdigest/digest.db` — SQLite (материалы, история, реакции, подписчики,
  здоровье источников, логи прогонов)
- `~/.newsdigest/profiles.json` — ваши темы и источники
- `~/.newsdigest/digest.log` — логи (ротация: 3 файла по 2 МБ)
- `~/.newsdigest/env` — секреты и настройки (права 600)

**Тесты:**

```bash
python3 -m unittest discover -s tests
```

Сеть и Telegram не трогаются: модель и транспорт подменяются заглушками.

## 💡 Советы

1. **Начинайте с `--dry-run`:** видно, какой будет выпуск, без отправки.
2. **Жмите 👍/👎 первую неделю** — без них отбор остаётся «средним по больнице».
3. **Логируйте всё:** `python3 digest.py -v --log-file daemon`.
4. **Мониторьте баланс DeepSeek** — он может закончиться. Проверяйте `doctor`.
5. **Резервируйте базу:** в ней история, реакции и подписчики.
   `cron` раз в неделю копирует `~/.newsdigest/digest.db`.

## 📞 Частые вопросы

**Q: Можно ли несколько чатов?**
A: Да, см. раздел «Несколько подписчиков». `/subs add <chat_id>` или `/start`
от нового чата.

**Q: Как добавить новый источник?**
A: `/feed add <ссылка>` в чате. Перезапуск не нужен.

**Q: Что если источник упал?**
A: После 5 сбоев подряд он отключается на сутки. Видно в `status` и `/status`.

**Q: Обновление сломает мою базу?**
A: Нет. История отправленного переезжает на новый формат на месте и достаётся
владельцу, `extra_chats` и пауза переносятся в подписчиков.

**Q: Как экспортировать новости?**
A: `sqlite3 ~/.newsdigest/digest.db "SELECT * FROM sent WHERE sent_at > '2026-01-01';"`
