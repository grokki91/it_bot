# 📰 News Digest Bot — Инструкция

Автоматический сбор и рассылка новостей в Telegram — по разделам: ИИ, железо,
роботы, космос, климат, наука, медицина, здоровье, политика, экономика, спорт,
происшествия, кино, игры. Выпуск приходит **дважды в день** — в назначенное
время и через 12 часов (по умолчанию 09:00 и 21:00), по 2 новости из каждого
раздела.

**В Telegram бот только рассылает.** Команд там нет: приходят выпуски и срочные
новости, разделы выпуска открываются кнопками, работают 👍/👎/🔖 — и всё. Страница в браузере
`http://<ip-вашего-vps>:8080/` — читалка: новостной сайт с лентой карточек,
разделами, поиском и закладками, уведомлениями о рассылках и настройками для
просмотра. **Управление — на самом VPS**: `python3 digest.py …` и
`~/.newsdigest/env`.

Работает на Python 3.8+, **без внешних зависимостей**, хранит всё в `~/.newsdigest/`.

---

## 🚀 Быстрый старт

### 1. Первичная настройка

```bash
python3 digest.py setup
```

Интерактивный мастер попросит:
- **Токен Telegram-бота** (от [@BotFather](https://t.me/BotFather))
- **Chat ID** (определит автоматически, если вы напишете боту сообщение)
- **API ключ DeepSeek** (platform.deepseek.com)
- **Раздел по умолчанию** — для срочных новостей и везде, где раздел не назван.
  Плановый выпуск идёт сразу по всем разделам, его состав задаёт `ND_SECTIONS`
- **Время отправки** (ваше локальное время, например 09:00)
- **Часовой пояс** (например `Europe/Riga`, `Europe/Moscow`)
- **Сколько выпусков в сутки** — 1 или 2 (второй через 12 часов)
- **Кол-во новостей** в выпуске (5–10)

Все данные сохранятся в `~/.newsdigest/env` с правами `600`.

### 2. Проверка подключений

```bash
python3 digest.py doctor
```

Проверяет:
- ✅ Telegram-бот и chat_id
- ✅ DeepSeek API и баланс
- ✅ Базу данных
- ✅ Часовой пояс

### 3. Тестовый прогон

```bash
python3 digest.py run --dry-run
```

Собирает и показывает дайджест в терминале, но **не отправляет** в Telegram.
Видно примерную стоимость запроса к LLM.

### 4. Запуск демона

```bash
python3 digest.py daemon
```

Фоновый процесс:
- Собирает новости каждые 4 часа (настраивается: `ND_COLLECT_EVERY`)
- Отправляет дайджест `ND_PER_DAY` раз в сутки: в `send_at` и дальше через
  равные промежутки (по умолчанию дважды — в 09:00 и 21:00)
- **Принимает нажатия кнопок** 👍/👎/🔖 и заявки новых чатов (команд в
  Telegram нет)
- **Держит страницу** на `http://<ip-вашего-vps>:8080/` (см. «Страница в браузере»)
- **Проверяет срочные новости** после каждого сбора
- Автоматически перезагружается при ошибках

**Как поднять на VPS:**

```bash
# Локально: сгенерировать unit-файл для systemd
python3 digest.py service > newsdigest.service

# На VPS (с sudo):
sudo cp newsdigest.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now newsdigest

# Проверить статус:
systemctl status newsdigest
```

Или проще (без root):
```bash
nohup python3 digest.py daemon --log-file >/dev/null 2>&1 &
```

> На VPS нужен весь каталог проекта (файл `digest.py` **и** папка `newsdigest/`),
> а не один файл. Команды запуска не изменились.

## 💬 Управление — на VPS

**Команд нет ни в Telegram, ни на странице.** Бот в чате только рассылает
выпуски: на любое сообщение приходит одна и та же справка — расписание и когда
ждать следующий выпуск:

```
🤖 Я только присылаю выпуски. Команд в чате нет.
🗓 Рассылка: 09:00 и 21:00 (Europe/Riga)
⏰ Следующий выпуск: сегодня, 16 августа в 21:00 — через 2 ч 20 мин
```

Так задумано: чат остаётся лентой новостей, страница — читалкой, а пульт лежит
на сервере. Ответ в чат идёт без звука и не чаще раза в полминуты на чат —
автоответчиком бот не работает. Совсем без ответа — `ND_CHAT_REPLY=off`: тогда
бот в чате молчит на всё, а кнопки под выпусками — и разделы, и 👍/👎/🔖 —
продолжают работать.

> Запретить писать боту Telegram не позволяет: окно ввода в чате убрать нельзя
> ни настройкой бота, ни через BotFather. «Закрытый чат» — это и есть бот,
> который на любое сообщение отвечает одной справкой (или молчит).

Всё, что раньше делалось командой, делается в терминале VPS — там же видно и
результат:

| Команда терминала | Что делает |
|-------------------|-----------|
| `python3 digest.py run` | Собрать и прислать весь выпуск прямо сейчас |
| `python3 digest.py run --dry-run` | То же, но показать на экране и не отправлять |
| `python3 digest.py run --section спорт --count 10` | Топ-N новостей одного раздела |
| `python3 digest.py collect` | Только собрать новости, без выпуска |
| `python3 digest.py status` | Расписание, расход, проблемные источники |
| `python3 digest.py feeds` | Проверить каждый источник по одному |
| `python3 digest.py topics` | Разделы и их источники (★ — в плановом выпуске) |
| `python3 digest.py doctor` | Проверить Telegram, DeepSeek и базу |

Настройки живут в `~/.newsdigest/env` (`ND_*`, см. «Все настройки») и
подхватываются при перезапуске демона; источники — в
`~/.newsdigest/profiles.json`; подписчики — в таблице `subscribers` базы
`~/.newsdigest/digest.db`. Текущие значения всегда видно на странице, в
«Настройках» — вместе со списком подписчиков.

Что осталось в Telegram: выпуски, срочные новости, кнопки 👍/👎/🔖 под ними и
заявки новых чатов (кнопки «✅ Пустить» / «🚫 Нет» владельцу). Совсем ничего не
принимать из чата — `ND_LISTEN=0`: тогда перестанут работать и кнопки.

> Команды `setup` и `chatid` определяют chat_id через `getUpdates`. Если демон
> запущен, Telegram ответит одному из них `409 Conflict` — остановите демон на
> время настройки.

## 🗂 Разделы

Раздел — это тема со своими источниками, своим портретом читателя и своим
отбором. Встроено семнадцать:

| Раздел | Имя в командах | Раздел | Имя в командах |
|--------|----------------|--------|----------------|
| 🤖 ИИ и технологии | `ai`, `ии`, `нейросети` | 🏛 Политика | `politics`, `политика` |
| 🖥 Компьютерное железо | `hardware`, `железо` | 💰 Экономика | `economy`, `экономика` |
| 🦾 Роботы | `robots`, `роботы`, `дроны` | ⚽ Спорт | `sports`, `спорт` |
| 🚀 Космос | `space`, `космос` | 🚨 Происшествия | `incidents`, `чп` |
| 🌍 Климат и экология | `climate`, `климат`, `экология` | 🎬 Кино и сериалы | `cinema`, `кино` |
| 🔬 Наука | `science`, `наука` | 🎮 Игры | `games`, `игры`, `гейминг` |
| 🩺 Медицина | `medicine`, `мед` | ₿ Криптовалюты | `crypto`, `крипта` |
| 🥗 Здоровье | `health`, `зож` | 🛡 Кибербезопасность | `cybersec`, `инфобез` |
|  |  | 📌 Свой раздел | `custom`, `свой` |

Имя можно писать как угодно: `medicine`, `Медицина`, `мед` — это один раздел.
Хватает и однозначного начала слова: `космо` → Космос.

**🌍 Климат вынесен из науки.** У него своя аудитория и свои источники
(Carbon Brief, Nature Climate Change, climate.gov, Inside Climate News, Yale
e360, Grist), а портрет читателя просит цифры и измерения вместо лозунгов. В
списке климат стоит **перед** наукой: одно событие показывается один раз, в
разделе, который идёт раньше, — иначе климатические новости так и оставались бы
в «Науке».

**🎮 Игры** — про индустрию, а не про прохождения: даты выхода и переносы,
патчи, техническое состояние релизов, сделки студий, движки. Источники:
GamesIndustry.biz, Game Developer, блоги PlayStation и Xbox, Eurogamer, Polygon,
PC Gamer, RPS, VGC, Nintendo Life, релизы Godot, DTF.

### Дважды в день: по паре новостей из каждого раздела

В 09:00 и в 21:00 (или во сколько скажете) приходит **одно сообщение** —
оглавление выпуска: что за выпуск, за какой день, сколько новостей, главное за
день и кнопки разделов. Раздел открывается прямо в этом же сообщении, «←
К разделам» возвращает назад. Порядок разделов постоянный, поэтому взгляд
быстро находит нужное.

```
☀️ ДНЕВНОЙ ВЫПУСК
18 августа · 23 новости

ГЛАВНОЕ СЕГОДНЯ

1. Демократы расследуют покупку акций Energy Fuels
Конгрессмены начали расследование: руководители компании купили тысячи акций…
🔗 grist · ⭐ 9.2

2. Amazon использовал редкие книги для обучения ИИ
Журналисты 404 Media отследили партию книг до объекта Amazon.
🔗 404media · ⭐ 8.0

3. llama.cpp b10472: исправлена проблема с памятью на AMD APU
Неточная оценка доступной памяти ломала запуск на машинах с малым выделением.
🔗 gh-llama-cpp · ⭐ 7.5

[ ⬇️ Ещё 4 главные новости      ]
[ 🤖 ИИ и технологии · 5        ]
[ 🌍 Климат и экология · 3      ]
[ 🖥 Компьютерное железо · 4    ]
[ 🔬 Наука · 2                  ]
[ 🏛 Политика и экономика · 5   ]
[ ☰ Остальные 8 разделов        ]
```

Нажали раздел — то же сообщение становится его экраном: новости целиком, с
сутью, «зачем это знать», источником и временем. Под каждой новостью её
кнопки 👍/👎/🔖, внизу — «← К разделам»:

```
🤖 ИИ и технологии
5 новостей · 18 августа

Amazon использовал редкие книги для обучения ИИ
Журналисты 404 Media отследили партию редких книг, которая в итоге оказалась
на объекте Amazon, предназначенном для обучения ИИ.
💡 Вскрывает масштаб нелегального использования книг для ИИ-обучения.
🔗 404media · ⭐ 8.0 · 20:48
...

[ 👍 Amazon использ… ] [ 👎 ] [ 🔖 ]
[ ⬇️ Ещё 2 новости                  ]
[ ← К разделам                      ]
```

Так шапка занимает две строки вместо пяти, а выпуск — одно сообщение вместо
трёх: до «Науки» теперь один тап, а не пролистывание всей ленты. Разделы, где
за сутки ничего не нашлось, названы на экране со списком разделов (кнопка
«☰ Остальные…») — молчание хуже, из него непонятно, бот пропустил раздел или
там правда пусто.

Новости не нумеруются (кроме главного за день, где номер — это место в
рейтинге): сквозная нумерация через разделы путала. Значка перед заголовком
нет: он повторял вывеску раздела. Время суток в шапке (🌅 утренний,
☀️ дневной, 🌆 вечерний, 🌙 ночной) берётся из времени сборки.

Выпуск, пришедший больше двух суток назад, листаться перестаёт: Telegram не
даёт ботам править старые сообщения. Текст последнего открытого экрана при
этом остаётся на месте, а вся история — на странице в браузере.

Кому привычнее прежний вид — сплошная лента одним текстом, при нужде в
два-три сообщения с пометкой «продолжение 2 из 3»:

```bash
export ND_TG_VIEW=feed     # или: python3 digest.py set view feed
```

Вечерний выпуск не повторяет утренний: история отправленного персональна, во
второй заход приходит только то, что появилось после первого. Расписание —
настройка `times`:

```bash
ND_PER_DAY=2         # два выпуска в сутки: в 09:00 и через 12 часов
ND_PER_DAY=1         # как раньше — один выпуск в день
ND_SEND_AT=08:30     # первый выпуск; второй сам сдвинется на 20:30
```

⚠️ Каждый выпуск — это отдельные запросы к модели на ранжирование и карточки,
поэтому два выпуска в сутки стоят примерно вдвое дороже одного. `python3
digest.py status` показывает расход за неделю.

```bash
ND_PER_SECTION=3                    # не 2 новости на раздел, а 3 (1–5)
ND_SECTIONS=кино,политика,спорт     # ровно эти разделы
ND_SECTIONS=все                     # включить вообще все
ND_SECTIONS=                        # вернуть подборку по умолчанию
```

Криптовалюты, кибербезопасность и «свой раздел» в подборку по умолчанию не
входят — их включают вручную. Список имён — `python3 digest.py topics`.

### По запросу: топ одного раздела

```bash
python3 digest.py run --section спорт              # 5 новостей
python3 digest.py run --section медицина --count 10
python3 digest.py run --section спорт --dry-run    # показать, не отправляя
```

Бот обходит **только источники этого раздела**, поэтому ответ приходит за
десятки секунд, а не за минуты. Плановый сбор от этого не сдвигается.

**Новости не повторяются.** Всё, что уже уходило вам — утром или по
`run --section`, — в следующий раз не придёт: история отправленного персональна
и живёт 60 дней. Внутри одного выпуска работает та же защита между разделами:
событие, о котором написали и в «Происшествиях», и в «Политике», покажется один
раз, в том разделе, который идёт раньше. Поэтому повторный запуск по спорту
даёт следующую десятку, а не ту же самую.

**Про расход.** Каждый раздел — свой запрос к модели на ранжирование (они идут
параллельно), карточки пишутся пачками на весь выпуск. Четырнадцать разделов
стоят примерно вдвое-втрое дороже одного, а два выпуска в сутки — вдвое дороже
одного; всё вместе это по-прежнему центы в день. Меньше разделов,
`ND_PER_SECTION=1` или `ND_PER_DAY=1` — дешевле; `python3 digest.py status`
показывает расход за неделю.

## 🖥 Страница в браузере

`http://<ip-вашего-vps>:8080/` — новостной сайт из ваших выпусков. Слева
разделы, в центре лента карточек, справа справка о выпуске, популярные
источники и темы. На телефоне то же самое одной колонкой с нижней навигацией.
Поднимается вместе с демоном, отдельно запускать ничего не нужно.

**Как зайти:**

```bash
# 1. Пароль страницы создался сам при первом запуске демона. Посмотреть:
grep ND_WEB_TOKEN ~/.newsdigest/env

# 2. Открыть в браузере (телефон, ноутбук — любой):
#    http://<ip-вашего-vps>:8080/
```

Пароль запоминается в браузере на 30 дней, так что вводится он один раз.

**Что там есть:**

- **Главное** — лента всех новостей, которые вам приходили: заголовок, текст
  новости, раздел, время, оценка модели ⭐ и ссылка на источник. Текст занимает
  три строки и разворачивается нажатием, так что понять новость можно не
  открывая источник. Внизу «Показать ещё»;
- **разделы** — слева списком (с числом новостей в каждом) и полосой плашек над
  лентой. Это фильтр по уже пришедшему, модель он не дёргает и денег не стоит;
- **поиск** — по заголовкам, сути, источникам и ссылкам. Понимает падежи:
  «Иране» находит и «Иран», и «Ирана»;
- **Сохранённые** и **Избранное** — то, что вы отметили 🔖 и 👍. Кнопки под
  карточкой те же, что в чате, и статистика вкусов у них общая: 👍 на странице
  влияет на следующий выпуск ровно так же, как 👍 в Telegram;
- **Популярные источники** — кто чаще всех доезжает до выпуска и какая у него
  средняя оценка. Нажатие ищет новости этого источника;
- **Популярные темы** — слова, которые чаще других встречаются в заголовках
  последних выпусков. Нажатие — тот же поиск;
- **Уведомления** — список рассылок: когда пришла, сколько было новостей и из
  скольких разделов, а под этим до пяти самых важных ссылок из выпуска. Ничего
  больше: переписки с ботом и истории запуска команд на странице нет;
- **Настройки** — подписчики (кто, какая роль, чем его настройки отличаются от
  общих) и все настройки приложения с текущими значениями — `breaking = вкл`,
  `time = 09:00` и так далее. Только для чтения: меняются они на VPS.

Лента собирается из истории отправленного: показывается ровно то, что вам уже
приходило. Ни ранжирования, ни карточек заново страница не заказывает — свежие
новости появляются в ней, когда придёт очередной выпуск.

Единственное исключение — язык: карточка, оставшаяся в истории английской (так
бывает у выпусков, собранных при недоступной модели, и у новостей, пришедших до
версии 3.5), переводится при первом же показе ленты и в переведённом виде в
истории и остаётся. Платится это один раз на новость, а если модель недоступна —
лента просто открывается с исходным текстом.

> 🖼 Картинок у новостей нет намеренно. В RSS они попадаются далеко не всегда, а
> грузить их со сторонних сайтов значит показывать этим сайтам, кто и когда
> читает вашу ленту. Вместо картинки — значок раздела на его цвете.

Страница только показывает: собрать выпуск, поменять настройку или одобрить
подписчика с неё нельзя — это делается на VPS. Единственное, что она меняет, —
ваши 👍/👎/🔖: кнопки под карточкой те же, что в чате. Работает страница от
имени владельца (`TELEGRAM_CHAT_ID`), поэтому видит его закладки, вкусы и
настройки.

**Настройки:**

```bash
export ND_WEB=1                # 0 — не поднимать страницу совсем
export ND_WEB_HOST=0.0.0.0     # 127.0.0.1 — только с самой машины
export ND_WEB_PORT=8080        # если 8080 занят nginx-ом
export ND_WEB_TOKEN=...        # пароль; пустой — создастся сам
```

Если порт занят, демон об этом напишет в лог и продолжит работать без страницы.

> ⚠️ **Это обычный HTTP без шифрования.** Для личного пользования на своём VPS
> этого достаточно, но пароль летит по сети открытым текстом. Кто хочет строже —
> `ND_WEB_HOST=127.0.0.1` и туннель:
> `ssh -L 8080:localhost:8080 user@vps`, дальше `http://localhost:8080/`.
> Порт 8080 стоит открыть только себе:
> `sudo ufw allow from <ваш-ip> to any port 8080`.

Страницу можно поднять и отдельным процессом — например, если демон крутится
под systemd, а страницу хочется перезапускать самостоятельно:

```bash
ND_WEB=0 python3 digest.py daemon     # демон без страницы
python3 digest.py web --port 8080     # страница отдельно
```

## 🌍 Язык выпуска: источники любые, лента русская

Источники намеренно международные — Reuters, Phoronix, Nature, arXiv: новость
берётся там, где её публикуют первой и достовернее всего, и отказываться от
первоисточника ради русской ленты неправильно. А вот показывать её читателю
по-английски — неправильно тоже, поэтому язык проверяется **после** модели, а не
только просьбой в промпте:

1. в готовой карточке ищется текст, на языке выпуска не написанный (для
   русского это дёшево — у него свой алфавит);
2. всё найденное уходит одним запросом на перевод: имена, названия продуктов и
   версии остаются как в оригинале (Nvidia, Linux 7.2, GPT-5), остальное
   переводится;
3. перевод оседает в базе — та же новость другому подписчику, а потом и в
   закладках достаётся уже без запроса к модели;
4. лента на странице проверяет язык ещё раз, у себя: история могла остаться
   английской (модель была недоступна в тот вечер, новость пришла до версии
   3.5) — такая карточка переводится при показе и в истории обновляется.

Проверка нужна как раз потому, что промпта мало: обычно модель пишет карточку
по-русски, но на английском источнике нет-нет да и оставит заголовок нетронутым,
а если саммари не написалось вовсе — в выпуск идёт заголовок прямо из фида.
Ровно так в русской ленте и появлялись английские карточки.

Ответ, не ставший русским, не берётся: модель иногда возвращает исходную строку,
и запомнить такое значило бы закрепить английский заголовок навсегда. Если
модель недоступна, выпуск всё равно уйдёт — с исходным заголовком, как раньше.

```bash
export ND_LANGUAGE=русский   # язык выпуска
export ND_TRANSLATE=0        # ничего не переводить: как ответила модель, так и шлём
```

Читателю, выбравшему себе другой язык (`language` в его строке подписчика),
ничего не переводится: определять произвольный язык алфавитом не выйдет, а
карточку модель и так пишет на его языке.

## 👍 Обратная связь: бот подстраивается

У каждой новости есть три кнопки: **👍**, **👎** и **🔖** (в закладки). Живут
они на экране раздела — по ряду на новость, подписанному началом заголовка
(«👍 llama.cpp: поддер…»): в разделе новостей единицы, и пульта из тридцати
кнопок не получается. Уже поставленные оценки видны галочкой, и она не
теряется при переходах: отметки расставляются заново из базы. Под срочной
новостью кнопки без подписи — новость там одна.

В старом виде (`ND_TG_VIEW=feed`) кнопки всего выпуска свёрнуты в одну строку
«👍 👎 🔖 Оценить новости (6)», нажатие разворачивает ряды, «▲ Свернуть» прячет
обратно; `ND_FEEDBACK_STYLE=rows` показывает их сразу.

Реакции идут в дело двумя путями:

1. **Прескоринг.** Источники и категории, которые вам нравятся, поднимаются в
   шорт-листе и чаще доезжают до модели. Вклад ограничен `feedback_weight`
   (по умолчанию 0.25), а сглаживание не даёт одной случайной реакции
   перевернуть картину.
2. **Промпт.** Модели показывают несколько недавних «зашло / не зашло» —
   с оговоркой, что по-настоящему важное событие публикуется в любом случае.

Что накопилось, видно в базе (таблица `feedback`) и по отметкам в ленте:
«Избранное» — всё, что вы поднимали 👍. Эффект заметен примерно через неделю.

```bash
export ND_FEEDBACK=0             # убрать кнопки совсем
export ND_FEEDBACK_STYLE=rows    # для ND_TG_VIEW=feed: не сворачивать ряды
export ND_FEEDBACK_WEIGHT=0      # оставить кнопки, но не влиять на отбор
```

## ⚡ Срочные новости

Событие, о котором за пару часов написали сразу несколько первоисточников, не
ждёт девяти утра. Ищется оно по всем вашим разделам сразу: землетрясение или
отставка правительства ждать должны не больше, чем релиз новой модели.
Проверка идёт после каждого сбора и требует **трёх** независимых подтверждений:

1. **Консенсус** — `breaking_min_sources` разных сайтов за `breaking_window_h`,
   и хотя бы один из них tier-1. Либо новость в одиночку набрала ~270+ баллов
   на Hacker News.
2. **Оценка модели** не ниже `breaking_min_score` (8.0 против обычных 5.5).
   Если модель недоступна, срочное **не** отправляется: без оценки слишком легко
   разбудить человека ради пересказа чужой новости.
3. **Приличия** — тихие часы, лимит в сутки, пауза рассылки.

Отправленное сразу попадает в историю, поэтому в плановом выпуске не повторится.

Проверка идёт не на каждого подписчика по отдельности: кандидаты зависят только
от набора разделов, поэтому читатели с одинаковым набором ранжируются одним
запросом к модели на всех. Личным остаётся всё остальное — история
отправленного, тихие часы, суточный лимит и язык карточки.

```bash
export ND_BREAKING=0                  # выключить совсем
export ND_BREAKING_QUIET=23:00-08:00  # часы тишины (или «нет»)
```

## 👥 Несколько подписчиков

Бот умеет обслуживать несколько чатов. У каждого своя история (дедупликация не
общая), свои разделы, своё время и свои лимиты.

- Новый чат пишет `/start` (или что угодно) → попадает в ожидание, владелец
  получает кнопки «✅ Пустить» / «🚫 Нет». Это единственное, что бот в Telegram
  ещё принимает от людей, кроме нажатий 👍/👎/🔖.
- `ND_SIGNUP=open` подписывает сразу, `ND_SIGNUP=off` возвращает поведение
  строго личного бота.
- Подписчик сам себя не настраивает: команд нет ни в чате, ни на странице.
  Общие настройки задаёт владелец в `~/.newsdigest/env`, личные лежат в базе
  (`sections`, `per_section`, `topic`, `send_at`, `tz`, `language`,
  `max_items`, `min_score`, `silent`) и продолжают работать: у кого они
  выставлены, тот получает своё.
- Список подписчиков и их отличия от общих настроек видно на странице,
  в «Настройках». Правится он в базе:

  ```bash
  sqlite3 ~/.newsdigest/digest.db \
    "INSERT INTO subscribers(chat_id,role,title,created_at)
     VALUES ('123456','member','Ваня',datetime('now'));"
  sqlite3 ~/.newsdigest/digest.db "DELETE FROM subscribers WHERE chat_id='123456';"
  sqlite3 ~/.newsdigest/digest.db \
    "UPDATE subscribers SET send_at='08:30' WHERE chat_id='123456';"
  ```

**Про расход:** новости собираются один раз на всех, а вот ранжирование и
карточки — свои для каждого подписчика. Расход на модель растёт примерно
пропорционально числу подписчиков.

## 📋 Команды терминала

| Команда | Что делает |
|---------|-----------|
| `setup` | Первичная настройка (токены, тема, время) |
| `chatid` | Переопределить chat_id без повторной настройки |
| `doctor` | Диагностика: проверить все подключения |

## ⚙️ Настройка

Настройки живут в двух местах:

1. **Файл `~/.newsdigest/env`** — всё, что перечислено ниже; читается при
   старте, так что после правки демон нужно перезапустить.
2. **`newsdigest/config.py`** — значения по умолчанию и то, чего нет в env.

Текущие значения всегда видно на странице, в «Настройках».

```bash
export ND_SECTIONS=ai,medicine,sports # Разделы выпуска. Пусто = подборка по умолчанию
export ND_PER_SECTION=2               # Новостей на раздел в выпуске (1-5)
export ND_TOPIC=ai                    # Раздел по умолчанию: срочные и всё безымянное
export ND_SEND_AT=09:00               # Время первого выпуска
export ND_PER_DAY=2                   # Выпусков в сутки (1-4): 2 = ещё через 12 часов
export ND_TZ=Europe/Moscow            # Часовой пояс (с переходом на летнее время)
export ND_COLLECT_EVERY=4             # Сбор каждые N часов
export ND_MIN_ITEMS=5                 # Минимум новостей, если раздел один
export ND_MAX_ITEMS=8                 # Максимум новостей, если раздел один
export ND_MIN_SCORE=5.5               # Порог важности (1–10)
export ND_LANGUAGE=русский            # Язык дайджеста
export ND_TRANSLATE=1                 # Переводить на него всё, что пришло на чужом
export ND_SILENT=1                    # Отправлять без звука
export ND_LISTEN=1                    # Принимать из чата кнопки и заявки (команд нет)
export ND_CHAT_REPLY=schedule         # Ответ на сообщение в чате: schedule | off
export ND_SIGNUP=ask                  # ask | open | off — как пускать новые чаты
export ND_TG_VIEW=screens             # screens — оглавление и разделы по кнопкам,
                                      # feed — сплошная лента одним текстом
export ND_FEEDBACK=1                  # Кнопки 👍/👎/🔖
export ND_FEEDBACK_STYLE=compact      # Для feed: compact — свёрнуты, rows — все сразу
export ND_FEEDBACK_WEIGHT=0.25        # Насколько реакции двигают отбор (0–1)
export ND_BREAKING=1                  # Срочные новости вне расписания
export ND_BREAKING_QUIET=23:00-08:00  # Часы тишины для срочного
export ND_WEB=1                       # Страница в браузере
export ND_WEB_HOST=0.0.0.0            # 127.0.0.1 = только через ssh-туннель
export ND_WEB_PORT=8080               # Порт страницы
export ND_WEB_TOKEN=...               # Пароль страницы (создаётся сам)
export TELEGRAM_BOT_TOKEN=...         # Токен бота
export TELEGRAM_CHAT_ID=...           # Chat ID владельца
export DEEPSEEK_API_KEY=...           # API ключ DeepSeek
```

## 🧩 Расширение и кастомизация

### Добавление источника — без правки кода

Свои источники лежат в `~/.newsdigest/profiles.json`:

```json
{
  "ai": {
    "feeds": [["my-blog", "https://example.com/rss", 1, "labs"]],
    "remove_feeds": ["theverge"],
    "keywords": ["mlops"]
  },
  "garden": {
    "title": "Дача", "emoji": "🌿", "aliases": ["дача", "сад"],
    "persona": "садовод, которому нужны сроки, сорта и погода",
    "keywords": [],
    "feeds": [["botanichka", "https://www.botanichka.ru/feed/", 2, "media"]]
  }
}
```

Для встроенного раздела правка **дополняет** его (а `remove_feeds` убирает
лишнее), поэтому обновление кода не затирает ваши источники. Новый раздел
описывается целиком и сразу появляется в `python3 digest.py topics` — останется
включить его в выпуск: `ND_SECTIONS=…,дача`. Сломанный JSON не роняет бота:
ошибка уходит в лог, работа продолжается на встроенных разделах.

Проверить, что фид жив и отдаёт новости, — `python3 digest.py feeds`.

Запись фида понимается в трёх видах: `"https://..."`, `["id", "url", tier,
"категория"]` или `{"url": "...", "tier": 1, "category": "labs"}`.

- **tier:** 1 = первоисточник, 2 = профильное СМИ, 3 = агрегатор/форум.
- **категории:** labs, research, opensource, media, community, business, policy, other.

### Замена LLM (например, на OpenAI)

В `newsdigest/config.py`:

```python
"llm_base":      "https://api.openai.com/v1",
"model_rank":    "gpt-4o-mini",
"model_summary": "gpt-4o-mini",
```

Ключ читается из `DEEPSEEK_API_KEY` — либо положите туда чужой ключ, либо
поправьте `newsdigest/llm.py`. Протокол ожидается OpenAI-совместимый
(`/chat/completions` с `response_format: json_object`).

### Изменение веса критериев ранжирования

В `newsdigest/config.py`, секция `WEIGHTS`:

```python
WEIGHTS = {
    "source_tier":   0.30,   # Первоисточник vs пересказ (↑ = доверие источникам)
    "corroboration": 0.25,   # Сколько сайтов пишут об этом (↑ = ищем консенсус)
    "social":        0.20,   # Баллы Hacker News (↑ = сообщество важнее)
    "freshness":     0.25,   # Свежесть новости (↑ = только горячее)
}
```

### Чистка базы и логов

```bash
# Удалить материалы старше 10 дней
sqlite3 ~/.newsdigest/digest.db "DELETE FROM items WHERE fetched_at < datetime('now', '-10 days');"

# Очистить всю базу (⚠️ потеряются история, реакции и дедупликация!)
rm ~/.newsdigest/digest.db

# Очистить логи
rm ~/.newsdigest/digest.log*
```

## 🛠 Troubleshooting

### Бот не отправляет новости

1. `python3 digest.py doctor`
2. `tail -50 ~/.newsdigest/digest.log | grep -i error`
3. `python3 digest.py status` — смотрите «Проблемные источники»

### Бот не отвечает на команды в Telegram

Так и задумано: команд нет ни в чате, ни на странице — бот только рассылает.
В ответ приходит справка о расписании: не чаще раза в полминуты на чат, а при
`ND_CHAT_REPLY=off` не приходит вовсе. Всё управление — на VPS, в терминале.

Если не работают **кнопки** 👍/👎/🔖 или заявки новых чатов:
- Проверьте, что демон запущен: `ps aux | grep "digest.py daemon"`
- В логе должна быть строка «Слушаю Telegram: кнопки под выпуском»
- `ND_LISTEN` не должен быть `0`
- Два процесса-демона одновременно работать не могут: Telegram отдаст
  `409 Conflict` одному из них

### Страница не открывается

1. Демон запущен? `ps aux | grep "digest.py daemon"` — страница живёт внутри него
2. В логе должна быть строка «Страница открыта: http://...». Если вместо неё
   «Страницу поднять не удалось» — порт занят, смените `ND_WEB_PORT`
3. Порт закрыт файрволом: `sudo ufw allow from <ваш-ip> to any port 8080`
4. Пароль забылся: `grep ND_WEB_TOKEN ~/.newsdigest/env`
5. `ND_WEB` не должен быть `0`

### Раздел всё время пустой

1. `python3 digest.py feeds` — видно, какие источники не отвечают. Раздел из
   семи фидов, где молчат все семь, новостей не даст
2. Уберите мёртвый источник и добавьте живой в `~/.newsdigest/profiles.json`
   (`remove_feeds` и `feeds`, см. «Расширение и кастомизация»)
3. Проверьте, не съели ли новости соседние разделы: одно событие показывается
   один раз, в том разделе, который идёт раньше. `python3 digest.py run
   --section <раздел> --dry-run` покажет, есть ли там что-то вообще
4. Свежесть: материалы старше `window_hours` (30 ч) в выпуск не попадают

### Новость пришла на английском

Так быть не должно: всё, что не на языке выпуска, переводится перед отправкой
(см. «Язык выпуска»). Если английская карточка всё же дошла:

1. `grep -i "перевод" ~/.newsdigest/digest.log` — видно, ходил ли бот за
   переводом и что ответила модель. «Перевод не удался» значит, что модель была
   недоступна: выпуск ушёл с исходным заголовком, следующий будет русским
2. `python3 digest.py doctor` — проверьте ключ и баланс DeepSeek
3. Загляните в «Настройки» на странице: `translate` должен быть «вкл»,
   а `language` — «русский» (проверка алфавитом работает для языка со своей
   письменностью)
4. Заголовок из одних имён и версий («Nvidia Rubin CES 2026») переводить нечего —
   он и по-русски выглядит так же
5. В браузере такую карточку чинит сама лента: откройте страницу, и английские
   заголовки уедут на перевод. Если после обновления они на месте — модель
   недоступна, смотрите пункт 2

### Неправильное время отправки

- Проверьте часовой пояс и расписание: `python3 digest.py doctor` — строка
  «Расписание» показывает все выпуски суток
- Пересохраните: `ND_TZ=Europe/Riga` в `~/.newsdigest/env` и перезапустите демон
- Второй выпуск идёт ровно через 12 часов после первого и отдельно не
  настраивается: сдвиньте `ND_SEND_AT`, сдвинутся оба
- Проверьте время на VPS: `timedatectl`

### Высокие расходы на DeepSeek

```bash
python3 digest.py status  # Видно расход за неделю
```

Чтобы снизить:
- `ND_PER_DAY=1` — один выпуск в сутки вместо двух: это сразу вдвое дешевле
- Уберите ненужные разделы: `ND_SECTIONS=…` без лишних — каждый раздел это
  отдельный запрос на ранжирование
- `ND_PER_SECTION=1` — по одной новости на раздел вместо двух
- Снизьте `section_candidates` в `config.py` (сколько кандидатов раздела
  видит модель)
- Уменьшите число подписчиков: у каждого свой выпуск, а значит и свои запросы
  к модели (срочные новости — исключение: там читатели с одинаковыми разделами
  идут одним запросом на всех)
- Выключите срочные: `ND_BREAKING=0`

### Исчезли старые новости

Нормально — удаляются через 10 дней (`keep_items_days`). История отправленного
живёт 60 дней (`keep_sent_days`) и нужна для защиты от повторов.

## 📊 Архитектура (для разработчиков)

```
digest.py                 ← точка входа, тонкая обёртка
newsdigest/
├── config.py             ← CFG, WEIGHTS, окружение, часовой пояс, логи
├── profiles.py           ← встроенные разделы: источники, портреты, названия
├── sections.py           ← имена разделов, разбор ввода, кто на какие подписан
├── userprofiles.py       ← ~/.newsdigest/profiles.json поверх встроенных
├── settings.py           ← что можно менять из чата и как это проверяется
├── net.py                ← HTTP: один opener, gzip, 308-редиректы
├── feedparse.py          ← разбор RSS/Atom и дат
├── textutil.py           ← канонизация ссылок, сигнатуры, похожесть
├── storage.py            ← SQLite: схема, миграции
├── subscribers.py        ← подписчики, личные настройки, расписание
├── sources.py            ← сбор из фидов и Hacker News
├── rank.py               ← кластеризация, прескоринг, отбор, история отправленного
├── feedback.py           ← реакции и их влияние на отбор
├── llm.py                ← ранжирование, карточки и перевод
├── translate.py          ← язык выпуска: проверка после модели и кэш переводов
├── telegram.py           ← транспорт Bot API
├── render.py             ← сборка текста из блоков-разделов и кнопок
├── issueview.py          ← выпуск экранами: оглавление, разделы, переходы
├── pipeline.py           ← конвейер выпуска: разделы, дедуп, отправка
├── breaking.py           ← срочные новости
├── bot.py                ← нажатия кнопок и переходы по выпуску, заявки, ответ в чате
├── daemon.py             ← расписание + long-poll
├── web.py                ← страница в браузере: HTTP, доступ, данные
├── newsfeed.py           ← лента страницы: выборки, поиск, язык, источники, темы
├── webpage.py            ← сама страница (HTML/CSS/JS одним файлом)
└── cli.py                ← аргументы командной строки
tests/                    ← смоук-тесты, сеть не трогают
```

**Четыре нити в демоне:**
- главная — long-poll `getUpdates`: нажатия кнопок и заявки новых чатов;
- `scheduler` — раз в минуту смотрит, не пора ли собрать или отправить;
- `worker` — выполняет тяжёлое по одной задаче за раз;
- `web` — HTTP-сервер страницы (нить на запрос, тот же `worker`).

**Страница и Telegram — одни и те же данные.** Страница ничего не считает
заново и ничем не управляет: лента, «Уведомления» и «Настройки» собираются из
той же истории и тех же настроек, по которым живёт рассылка. Единственное
действие, доступное с неё, — 👍/👎/🔖, и они попадают туда же, куда нажатия в
чате. Копии отправленных сообщений по-прежнему лежат в `outbox`, но нужны они
теперь только Telegram: по ним бот разворачивает свёрнутые ряды кнопок.

**Лента новостей — это история отправленного.** Вместе с каждой новостью в
таблицу `sent` пишется и сама карточка: раздел, заголовок, суть и оценка
модели. Из этих строк `newsfeed.py` и собирает ленту — фильтр по разделу,
поиск, закладки, популярные источники и темы. Ничего не пересчитывается,
поэтому страница открывается мгновенно. У истории, собранной прошлыми версиями,
этих полей нет: раздел таким новостям лента определит по источнику, суть
достанет из самого материала (`items`), а звёздочку не покажет. Английская
карточка на этом же шаге доводится до языка выпуска — сначала кэшем переводов,
и лишь за остатком одним запросом к модели; результат пишется обратно в `sent`,
так что второй раз он не стоит ничего, а поиск начинает находить новость по
русским словам.

**Выпуск живёт в базе.** Отправленный выпуск целиком (разделы, карточки,
оценки) кладётся в таблицу `issues`, а в кнопке едет только его номер: в
`callback_data` всего 64 байта, и через час, когда читатель нажмёт «Наука», ни
кластеров, ни ответа модели уже нет. Хранится десяток последних выпусков на
чат — Telegram всё равно не даёт править сообщения старше двух суток. Нажатие
раздела собирает экран заново и переписывает то же сообщение
(`editMessageText`), поэтому чат не растёт от навигации.

**Расписание.** У каждого дня столько выпусков, сколько сказано в `per_day`:
первый в `send_at`, дальше через равные промежутки. Отправленный выпуск
помечается в базе строкой «дата#номер» (`2026-08-15#2`), поэтому вечерний
выпуск не считается «уже отправленным» из-за утреннего, а пропущенный не
догоняется двумя подряд.

**Данные:**
- `~/.newsdigest/digest.db` — SQLite (материалы, история, реакции, подписчики,
  здоровье источников, логи прогонов, карточки для ленты страницы, последние
  выпуски для переходов по разделам и последние 400 сообщений для
  «Уведомлений»)
- `~/.newsdigest/profiles.json` — ваши разделы и источники
- `~/.newsdigest/digest.log` — логи (ротация: 3 файла по 2 МБ)
- `~/.newsdigest/env` — секреты и настройки (права 600)

**Тесты:**

```bash
python3 -m unittest discover -s tests
```

Сеть и Telegram не трогаются: модель и транспорт подменяются заглушками.

## 💡 Советы

1. **Начинайте с `--dry-run`:** видно, какой будет выпуск, без отправки.
2. **Жмите 👍/👎 первую неделю** — без них отбор остаётся «средним по больнице».
3. **Логируйте всё:** `python3 digest.py -v --log-file daemon`.
4. **Мониторьте баланс DeepSeek** — он может закончиться. Проверяйте `doctor`.
5. **Резервируйте базу:** в ней история, реакции и подписчики.
   `cron` раз в неделю копирует `~/.newsdigest/digest.db`.

## 📞 Частые вопросы

**Q: Куда делись команды?**
A: Их нет ни в Telegram, ни на странице. В чате бот только рассылает выпуски и
на любое сообщение отвечает справкой о расписании; страница — читалка. Всё
управление на самом VPS: `python3 digest.py run | collect | status | feeds |
topics | doctor` и `~/.newsdigest/env`. Кнопки под выпусками работают как
работали: разделы, 👍/👎/🔖 — и то же самое под карточками на странице.

**Q: Можно вообще закрыть чат с ботом, чтобы туда нельзя было писать?**
A: Со стороны Telegram — нет: окно ввода в личном чате с ботом не убирается ни
настройкой, ни через BotFather. Максимум, что можно, — чтобы бот ничего не
делал в ответ: `ND_CHAT_REPLY=off` (молчит на всё, кнопки под выпусками
работают) или `ND_LISTEN=0` (не читает чат вообще — вместе с кнопками
и заявками новых чатов).

**Q: Как часто приходит выпуск?**
A: Дважды в сутки — в `send_at` и через 12 часов. `ND_PER_DAY=1` вернёт один
выпуск в день, `ND_PER_DAY=3` сделает три (каждые 8 часов). Второй выпуск
собирается из того, что появилось после первого, — повторов не будет.

**Q: Можно ли несколько чатов?**
A: Да, см. раздел «Несколько подписчиков»: новый чат пишет боту и владелец
пускает его кнопкой, либо строка добавляется в таблицу `subscribers` руками.
У каждого свой список разделов.

**Q: Я обновился со старой версии — куда делась моя тема?**
A: Никуда. Личная тема подписчика при обновлении стала его личным списком
разделов, выпуск не изменился. Хотите больше — допишите разделы в
`ND_SECTIONS`. У владельца (общая тема из `ND_TOPIC`) плановый выпуск
становится подборкой по всем разделам; вернуть как было — `ND_SECTIONS=<ваша
тема>`.

**Q: Почему источники англоязычные, если выпуск русский?**
A: Потому что новость берётся там, где она достовернее: Reuters, Phoronix,
Nature, arXiv. Язык источника читателя не касается — карточка приходит на языке
выпуска, а что осталось на чужом, переводится перед отправкой (раздел «Язык
выпуска»). Русские источники в разделах тоже есть, и добавить свои никто не
мешает: `~/.newsdigest/profiles.json`.

**Q: Сколько стоит перевод?**
A: Копейки: переводятся только те строки, что остались на чужом языке, все
разом одним запросом, и каждая — один раз (дальше берётся из базы). Совсем
выключить — `ND_TRANSLATE=0`.

**Q: Как добавить новый источник?**
A: Дописать его в `~/.newsdigest/profiles.json` (раздел «Расширение и
кастомизация») и перезапустить демон. Проверить — `python3 digest.py feeds`.

**Q: Что если источник упал?**
A: После 5 сбоев подряд он отключается на сутки. Видно в
`python3 digest.py status`.

**Q: Обновление сломает мою базу?**
A: Нет. История отправленного переезжает на новый формат на месте и достаётся
владельцу, `extra_chats` и пауза переносятся в подписчиков.

**Q: Можно совсем не открывать Telegram?**
A: Для чтения — да: на странице (`http://<ip-вашего-vps>:8080/`) есть лента с
разделами, поиском и закладками, а в «Уведомлениях» — все рассылки со ссылками
на главное. Бот при этом продолжает слать выпуски и в чат: одно другому не
мешает.

**Q: На странице пусто, хотя выпуски приходят.**
A: Лента строится из истории отправленного, и первый выпуск после обновления
её наполнит. Если истории нет совсем — соберите выпуск на VPS:
`python3 digest.py run`.

**Q: Страница видна из интернета — это безопасно?**
A: Она закрыта паролем, но HTTP не шифрован. Для личного VPS нормально;
надёжнее — `ND_WEB_HOST=127.0.0.1` плюс `ssh -L 8080:localhost:8080 user@vps`.

**Q: Как экспортировать новости?**
A: `sqlite3 ~/.newsdigest/digest.db "SELECT * FROM sent WHERE sent_at > '2026-01-01';"`
