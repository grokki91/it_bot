# 📰 News Digest Bot

Собирает новости из RSS и присылает выпуск в Telegram — дважды в день, по
восемнадцати разделам (ИИ, софт, кибербез, железо, роботы, космос, климат,
наука, медицина, здоровье, политика, экономика, спорт, происшествия, кино,
игры, крипта, свой). Раздел определяется по содержанию новости, а не по ленте,
из которой она пришла. Важные события приходят вне расписания.

- **Telegram** — только рассылка: выпуски, срочное, кнопки 👍/👎/🔖 и «⭐ Мои
  темы». Команд нет.
- **Страница** `http://<ip-вашего-vps>:8080/` — читалка: лента, разделы, поиск,
  закладки. Новости открыты всем, служебное — по паролю.
- **Управление** — на VPS: `python3 digest.py …` и `~/.newsdigest/env`.

Python 3.8+, без внешних зависимостей, всё хранится в `~/.newsdigest/`.

## 🚀 Быстрый старт

```bash
python3 digest.py setup       # мастер: токен бота, chat_id, ключ DeepSeek, время, TZ
python3 digest.py doctor      # проверить Telegram, DeepSeek, базу, часовой пояс
python3 digest.py run --dry-run   # собрать выпуск и показать в терминале
python3 digest.py daemon      # рабочий режим
```

`setup` пишет `~/.newsdigest/env` с правами 600. Токен бота — у
[@BotFather](https://t.me/BotFather), ключ — на platform.deepseek.com.

> `setup` и `chatid` определяют chat_id через `getUpdates`. Если демон запущен,
> Telegram ответит одному из них `409 Conflict` — остановите демон на время настройки.

**Демон** собирает новости каждые 4 часа, шлёт выпуски по расписанию, проверяет
срочное раз в 15 минут, принимает нажатия кнопок и держит страницу.

На VPS — через systemd (нужен весь каталог проекта: `digest.py` **и** `newsdigest/`):

```bash
python3 digest.py service > newsdigest.service
sudo cp newsdigest.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now newsdigest
```

Или без root: `nohup python3 digest.py daemon --log-file >/dev/null 2>&1 &`

### Автообновление после мержа в master

Чтобы не заходить на VPS с `git pull` и `systemctl restart` после каждого
мержа, поставьте таймер: он раз в 5 минут смотрит на `origin/main` и, если
появились новые коммиты, подтягивает их и перезапускает демона.

```bash
python3 digest.py autoupdate          # напечатает и сохранит юнит + таймер
sudo cp ~/.newsdigest/newsdigest-update.service \
        ~/.newsdigest/newsdigest-update.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now newsdigest-update.timer
```

Работает только если код на сервере получен через `git clone`. Таймер вызывает
`deploy/autoupdate.sh`, который:

* молчит, когда новых коммитов нет — journal от него не растёт;
* ничего не делает, если на сервере другая ветка или есть незакоммиченные
  правки (ваши локальные изменения не будут потеряны);
* тянет только `--ff-only`, git-командами от владельца каталога, а не от root
  (через `setpriv`, поэтому в journal не сыплются PAM-строки на каждый тик);
* не перезапускает демона, если изменилась одна документация.

Параметры: `--branch`, `--minutes`, `--service` у команды `autoupdate`;
`Environment=ND_SELFTEST=1` в юните — прогонять тесты перед перезапуском и
откатываться на прежний коммит, если они упали.

Проверить: `systemctl list-timers newsdigest-update --no-pager` и
`journalctl -u newsdigest-update -n 20 --no-pager`.

## 📋 Команды

| Команда | Что делает |
|---------|-----------|
| `setup` / `chatid` | Первичная настройка / переопределить chat_id |
| `doctor` | Диагностика подключений |
| `run` | Собрать и отправить выпуск сейчас |
| `run --dry-run` | То же, но показать в терминале |
| `run --section спорт --count 10` | Топ-N новостей одного раздела |
| `run --no-collect` | Отправить из уже собранных новостей |
| `collect` | Только собрать новости |
| `status` | Прогоны, расход DeepSeek, проблемные источники, срочное за неделю |
| `report [--days 30]` | Итоги за период: разделы, источники, маршрутизация, реакции |
| `feeds` | Проверить каждый источник (`--url <ссылка>` — одну ленту) |
| `feeds --candidates [--adopt]` | Кто из кандидатов отвечает / добавить их |
| `topics` | Разделы и их источники (★ — в плановом выпуске) |
| `daemon` / `web` | Фоновый режим / только страница |
| `scrub [файл]` | Вычистить секреты из файла или stdin — перед вставкой в issue или PR (`--check` — только проверить) |
| `service` | Вывести systemd unit-файл |
| `autoupdate` | Юнит и таймер: сам `git pull` + перезапуск демона после мержа |

Глобальные флаги: `-v` (DEBUG-логи), `--log-file` (писать в `~/.newsdigest/digest.log`).

## 🗂 Разделы и выпуск

Имя раздела пишется как угодно и хватает однозначного начала слова:
`medicine`, `Медицина`, `мед`, `космо`. Полный список — `digest.py topics`.

Выпуск приходит **одним сообщением**: оглавление с главным за день и кнопками
разделов, раздел открывается прямо в нём, «← К разделам» возвращает назад.
Пустые разделы названы явно. Выпуск старше двух суток листаться перестаёт —
Telegram не даёт ботам править старые сообщения; вся история есть на странице.

Вечерний выпуск не повторяет утренний, и одно событие показывается один раз
даже если попало сразу в два раздела. История отправленного персональна и
живёт 60 дней.

**Свой порядок разделов.** Кнопка «⭐ Мои темы» под оглавлением (и под ответом
бота на любое сообщение в чате) открывает список разделов: отмеченные — до пяти
— идут в выпуске первыми, остальные следом. Порядок тот, в котором отмечали.
Это ещё и приоритет при разборе: событие, попавшее сразу в два раздела,
достаётся тому, что стоит выше. Отмечает каждый подписчик себе сам; владелец
задаёт этой же кнопкой порядок по умолчанию для всех (`ND_FAVORITES`).

```bash
ND_FAVORITES=спорт,космос           # до 5 разделов первыми (пусто = обычный порядок)
ND_PER_DAY=2                        # выпусков в сутки (второй через 12 часов)
ND_SEND_AT=08:30                    # время первого; второй сдвинется сам
ND_PER_SECTION=3                    # новостей на раздел (1–5)
ND_SECTIONS=кино,политика,спорт     # ровно эти разделы (пусто = подборка по умолчанию)
ND_TG_VIEW=feed                     # прежний вид: сплошная лента одним текстом
```

⚠️ Каждый выпуск — отдельные запросы к модели, поэтому два выпуска в сутки
стоят примерно вдвое дороже одного. Расход видно в `digest.py status`.

## 🖥 Страница в браузере

Поднимается вместе с демоном. Слева разделы, в центре лента карточек, справа
справка о выпуске, популярные источники и темы; на телефоне — одна колонка.

**Гость** видит обычный новостной сайт: лента, разделы, фильтры, поиск. Ничего
служебного ему не приходит по сети вовсе — разделение сделано на сервере.
**Владелец** жмёт 🔑 в шапке и вводит пароль (`grep ND_WEB_TOKEN ~/.newsdigest/env`,
запоминается на 30 дней) — добавляются «Уведомления», «Сохранённые»,
«Избранное», «Настройки» и кнопки 👍/👎/🔖 под карточками.

Лента строится из истории отправленного: заново ничего не считается и денег не
стоит. Срочные новости выделены красной рамкой. Поиск понимает падежи. Картинок
нет намеренно — грузить их со сторонних сайтов значит показывать этим сайтам,
кто и когда читает вашу ленту.

Менять со страницы можно только свои 👍/👎/🔖 — остальное на VPS.

```bash
ND_WEB=1            # 0 — не поднимать страницу
ND_WEB_HOST=0.0.0.0 # 127.0.0.1 — только с самой машины
ND_WEB_PORT=8080
ND_WEB_TOKEN=...    # пароль владельца; пустой — создастся сам
```

> ⚠️ Это обычный HTTP: пароль летит по сети открытым текстом. Строже —
> `ND_WEB_HOST=127.0.0.1` и туннель `ssh -L 8080:localhost:8080 user@vps`.

## 🧠 Как это работает

**Маршрутизация по разделам** (`classify.py`) — каскад от бесплатного к дорогому:
узкая лента (раздел берётся из фида) → словарь правил по заголовку и лиду →
модель, только для широких лент и пачкой с кэшем. Не решилось — новость доберётся
по источнику. Точность словаря меряется набором `tests/data/routing.json` (66
размеченных заголовков): увидели новость не в своём разделе — добавьте её туда.

**Дедупликация** в два слоя. Первый — слова: у пересказа одной новости общих
слов много, и порог `similarity` сводит такие заметки в один кластер. Он же
защищает от повторов между выпусками — по истории `sent` за 60 дней.

Слов хватает не всегда. «Тим Карри, звезда «Шоу ужасов Рокки Хоррора», умер в
80 лет» и «Коллеги, включая Кэрол Бернетт и Люка Эванса, прощаются с Тимом
Карри» — одно событие, но общее слово у них ровно одно, и по словам это разные
новости: вечером выпуск, ночью то же самое срочным.

Поэтому спорную зону (совпадение ниже `similarity`, но не ниже `dup_gray`)
разбирает модель — `dedup.py`. Вопрос ей задаётся один: это одно и то же
событие? Причина смерти, число жертв, реакция властей — это уже следующая
новость, и она приходить должна; сомневается — отвечает «разные». Спрашиваем
только про верхушку разделов и только про недавнее, парами вперемешку и одним
пачками по `dup_batch` (сотня пар одним куском упирается в потолок ответа, и
обрыв стоил бы всех вердиктов разом). Спорных пар в выпуске из полутора десятков
разделов набирается под сотню, поэтому порядок вопросов решает: сначала те пары,
что дадут дубль прямо сейчас (повтор истории и два кандидата одного раздела),
внутри очереди — самые весомые (общая фамилия весит больше общего слова
«компания»). Вердикт кэшируется в таблице `dupes`. Модель недоступна или
`ND_DUP_LLM=0` — работает первый слой, как работал раньше.

Найденное применяется по-разному. Совпало с историей — кандидата убираем.
Совпали два кандидата **одного раздела** — их кластеры склеиваются в один
(`dedup.fuse`): карточку пишет модель по материалам кластера, так что вместо
двух блоков читатель получает один — и подробностей в нём больше, чем было в
каждой заметке по отдельности. Ничего при этом не выбрасывается: у той заметки,
что информативнее, оценка бывает ниже, и выбирать между ними не приходится.
Совпали кандидаты **разных разделов** — их только связывают, и второй отпадёт,
лишь если первый действительно попадёт в выпуск: склейка решила бы за отбор, в
каком разделе новости жить.

**Срочные новости** требуют трёх подтверждений: консенсус разных **издателей**
за окно (агентства AP/Reuters достаточно вдвоём; либо ~270+ баллов на HN),
оценка срочности отдельным промптом по шкале агентств (масштаб события, а не
«интересно ли читателю»), и приличия — тихие часы, суточный лимит, пауза. Два
уровня: ⚡ молния (≥9.0) уходит сразу, 🔔 важное (≥7.5) копится и приходит
сводкой. Агентства и службы оповещения (USGS, GDACS, CISA, ЦБ…) опрашиваются
по быстрой полосе раз в 15 минут, а магнитуда и уровень тревоги из заголовка
поднимают оценку без запросов к модели (`signals.py`).

**Язык.** Источники международные, лента русская: после модели карточка
проверяется на чужой язык, всё найденное уходит одним запросом на перевод
(имена и версии остаются как есть), результат оседает в базе — второй раз
бесплатно. Модель недоступна — выпуск уйдёт с исходным заголовком.

**Обратная связь.** 👍/👎/🔖 поднимают ваши источники и категории в прескоринге
(вклад ограничен `feedback_weight`) и показываются модели как «зашло/не зашло».
Эффект заметен примерно через неделю.

**Доверие к источнику** (`trust.py`): `kind` (wire, primary, independent, pr,
state, aggregator…) задаёт достоверность, `publisher` — по кому считается
консенсус, `wire` — быстрая полоса, `strict` — узкий фид. Поэтому пресс-релиз
не выигрывает у разбора, а шесть лент Guardian не считаются шестью
подтверждениями.

## 🔒 Секреты: что и куда не уходит

Правило одно: **токен бота, ключ модели и пароль страницы не видит никто —
ни языковая модель, ни лог, ни issue, ни pull request.** Держится оно не на
аккуратности, а на фильтре `newsdigest/redact.py`, который стоит на каждом
выходе наружу.

**Где живут секреты.** Только в `~/.newsdigest/env` (права 600, в git не
попадает — он в `.gitignore`). В коде их нет и быть не должно.

**Что уходит к модели.** Заголовки и первые абзацы новостей из открытых лент,
имена источников, портрет читателя (`persona`) и заголовки, которые вы
отметили 👍/👎. Больше ничего: ваши сообщения в чат к модели не идут вовсе,
переписки с ней нет.

**Почему этого мало.** Текст запроса собирается не только нами. Портрет
читателя правится руками в `profiles.json`, источники добавляет владелец, а
содержимое лент приходит из интернета. Достаточно один раз добавить фид вида
`https://example.com/rss?api_key=…` — и ключ уехал бы к модели вместе с  <!-- nd-redact: allow -->
карточкой. Поэтому `llm.llm_json` — единственная дверь к модели, и все
сообщения запроса чистятся прямо в ней, **до** отправки. Смените провайдера
или модель, добавьте новый промпт — защита останется на месте: она смотрит на
сообщения, а не на имена наших промптов. Если что-то вырезано, в логе
появляется предупреждение (без самой находки) — проверьте `profiles.json` и
адреса источников.

**Что именно вырезается:**

* известные живые значения — токен Telegram, ключ модели, пароль страницы и
  всё, что лежит в окружении под именем вроде `*_TOKEN`, `*_KEY`, `*_SECRET`;
* логин и пароль в ссылке: `https://user:пароль@host/feed`;  <!-- nd-redact: allow -->
* ключи в параметрах ссылки: `?api_key=`, `&access_token=`, `&sig=`;  <!-- nd-redact: allow -->
* пары «имя = значение» с говорящим именем — `DEEPSEEK_API_KEY=…`,
  `"password": "…"`, `пароль от панели: …`;
* узнаваемые ключи: `sk-…`, `ghp_…`, `xox…`, `AKIA…`, `AIza…`, JWT,
  `-----BEGIN PRIVATE KEY-----`;
* заголовки `Authorization: Bearer …`.

Вместо находки остаётся `[скрыто]`. Общего поиска «длинной строки со
случайными буквами» нет сознательно: через тот же фильтр идут новости, и
испорченный заголовок хуже перестраховки. Поэтому в ленте спокойно остаются
`?q=ai&hl=ru`, «Токен на бирже: Binance объявила...» и прочая живая речь.

**Лог и терминал.** `SecretFilter` висит на всех обработчиках логов
(`config.setup_logging`), поэтому в `~/.newsdigest/digest.log` секрет не
запишется, даже если попадёт туда через сообщение об ошибке или адрес ленты.
Пароль страницы в лог не пишется вовсе — только «создан и сохранён в env».
Адреса источников печатаются без ключей.

**Перед issue или pull request.** Всё, что вы собрали руками, прогоняйте
через ту же машинку:

```bash
python3 digest.py scrub ~/.newsdigest/digest.log > safe.log   # вычистить
python3 digest.py scrub --check safe.log                      # проверить
```

`--check` ничего не печатает, а возвращает код 1, если в файле осталось
похожее на секрет — этим же занимается проверка в CI на каждый push и pull
request (`.github/workflows/checks.yml`). Заведомо игрушечный пример в
документации или тесте помечается в той же строке комментарием
`nd-redact: allow` — проверка её пропустит.

**Чего фильтр не заменяет.** Он последний рубеж, а не первый: не вставляйте
в issue содержимое `~/.newsdigest/env`, не публикуйте `profiles.json` с
приватными лентами и не носите ключи в адресах, если ленту можно завести без
них. Ключ, который всё-таки где-то засветился, отзывается и перевыпускается —
фильтр вырезает его из текста, но не отменяет.

## 👥 Несколько подписчиков

Новый чат пишет боту → владелец получает кнопки «✅ Пустить» / «🚫 Нет»
(`ND_SIGNUP=open` — сразу, `off` — строго личный бот). У каждого своя история,
свои разделы, время и лимиты. Сам себе подписчик настраивает только порядок
разделов — кнопкой «⭐ Мои темы»; остальное правится на VPS: общее — в `env`,
личное — в таблице `subscribers` (`sections`, `favorites`, `per_section`,
`send_at`, `tz`, `language`, `max_items`, `min_score`, `silent`).

```bash
sqlite3 ~/.newsdigest/digest.db \
  "INSERT INTO subscribers(chat_id,role,title,created_at)
   VALUES ('123456','member','Ваня',datetime('now'));"
sqlite3 ~/.newsdigest/digest.db "UPDATE subscribers SET send_at='08:30' WHERE chat_id='123456';"
sqlite3 ~/.newsdigest/digest.db "UPDATE subscribers SET favorites='sports,space' WHERE chat_id='123456';"
```

Новости собираются один раз на всех, а ранжирование и карточки — свои для
каждого: расход растёт пропорционально числу подписчиков.

## 🧩 Кастомизация

**Свои источники и разделы** — `~/.newsdigest/profiles.json`, без правки кода:

```json
{
  "ai": {
    "feeds": [["my-blog", "https://example.com/rss", 1, "labs"]],
    "remove_feeds": ["theverge"]
  },
  "garden": {
    "title": "Дача", "emoji": "🌿", "aliases": ["дача", "сад"],
    "persona": "садовод, которому нужны сроки, сорта и погода",
    "feeds": [["botanichka", "https://www.botanichka.ru/feed/", 2, "media"]]
  }
}
```

Для встроенного раздела правка **дополняет** его, поэтому обновление кода не
затирает ваши источники. Сломанный JSON не роняет бота. Фид описывается строкой,
кортежем `["id", "url", tier, "категория"]` или объектом; tier: 1 —
первоисточник, 2 — профильное СМИ, 3 — агрегатор. Проверить — `digest.py feeds`.

**Кандидаты.** Список фидов стареет сам (AnandTech закрылся, у Reuters пропал
публичный RSS), поэтому кандидаты живут отдельно (`candidates.py`) и попадают в
подборку, только если ответили: `digest.py feeds --candidates --adopt`.

**Молчащие источники** — те, что отвечают 200 и отдают ноль записей — видно в
`status` после `quiet_after_empty` пустых обходов подряд.

**Другая LLM** — в `config.py` поменять `llm_base`, `model_rank`,
`model_summary`; ключ читается из `DEEPSEEK_API_KEY`. Протокол ожидается
OpenAI-совместимый.

**Веса ранжирования** — `WEIGHTS` в `config.py`: `trust` 0.30,
`corroboration` 0.25, `social` 0.20, `freshness` 0.25.

**Чистка:**

```bash
sqlite3 ~/.newsdigest/digest.db "DELETE FROM items WHERE fetched_at < datetime('now','-10 days');"
rm ~/.newsdigest/digest.db      # ⚠️ потеряются история, реакции и дедупликация
rm ~/.newsdigest/digest.log*
```

## 🛠 Troubleshooting

**Не приходят выпуски** — `digest.py doctor`, затем `grep -i error
~/.newsdigest/digest.log` и «Проблемные источники» в `status`.

**Бот не отвечает на команды** — так и задумано, команд нет. Если не работают
**кнопки**: демон запущен (`ps aux | grep "digest.py daemon"`)? `ND_LISTEN` не
`0`? Два демона одновременно нельзя — Telegram отдаст одному `409 Conflict`.

**Страница не открывается** — она живёт внутри демона. В логе должна быть
строка «Страница открыта: http://…»; «Страницу поднять не удалось» = порт занят,
смените `ND_WEB_PORT`. Ещё проверьте файрвол
(`sudo ufw allow from <ваш-ip> to any port 8080`) и `ND_WEB`.

**Раздел всё время пустой** — `digest.py feeds` покажет молчащие ленты; уберите
мёртвые и добавьте живые в `profiles.json`. Ещё вариант: событие забрал соседний
раздел (`run --section <раздел> --dry-run` покажет, есть ли там что-то) или
материалы старше `window_hours` (30 ч).

**Новость на английском** — `grep -i "перевод" ~/.newsdigest/digest.log`: «Перевод
не удался» значит, модель была недоступна. Проверьте баланс (`doctor`) и что
`translate` = вкл. На странице такие карточки чинятся сами при показе ленты.

**Неправильное время** — `doctor` показывает всё расписание суток; проверьте
`ND_TZ` и `timedatectl` на VPS. Второй выпуск идёт ровно через 12 часов после
первого и отдельно не настраивается.

**Дорого** — `ND_PER_DAY=1` (сразу вдвое дешевле), меньше разделов в
`ND_SECTIONS`, `ND_PER_SECTION=1`, ниже `section_candidates` в `config.py`,
`ND_BREAKING=0`.

**Исчезли старые новости** — нормально: материалы живут 10 дней
(`keep_items_days`), история отправленного — 60 (`keep_sent_days`).

**Источник упал** — после 5 сбоев подряд отключается на сутки, видно в `status`.

## 📊 Архитектура

```
digest.py                 ← точка входа, тонкая обёртка
newsdigest/
├── config.py             ← CFG, WEIGHTS, окружение, часовой пояс, логи
├── profiles.py           ← встроенные разделы: источники, портреты, названия
├── sections.py           ← имена разделов, разбор ввода, подписки
├── userprofiles.py       ← profiles.json поверх встроенных
├── settings.py           ← настройки и их проверка
├── net.py / feedparse.py ← HTTP, разбор RSS/Atom
├── textutil.py           ← канонизация ссылок, сигнатуры, похожесть
├── storage.py            ← SQLite: схема, миграции
├── subscribers.py        ← подписчики, личные настройки, расписание
├── sources.py            ← сбор из фидов и Hacker News
├── rank.py               ← кластеризация, прескоринг, отбор, история
├── feedback.py           ← реакции и их влияние на отбор
├── trust.py              ← реестр источников: издатель, класс, доверие
├── classify.py           ← раздел новости по её содержанию
├── signals.py            ← числовые сигналы срочности
├── candidates.py         ← источники-кандидаты
├── llm.py / translate.py ← ранжирование, карточки, перевод и его кэш
├── redact.py            ← заслон для секретов: промпты, логи, вывод команд
├── telegram.py           ← транспорт Bot API
├── render.py             ← сборка текста из блоков и кнопок
├── issueview.py          ← выпуск экранами: оглавление, разделы, переходы
├── prefsview.py          ← экран «Мои темы»: свой порядок разделов кнопками
├── pipeline.py           ← конвейер выпуска
├── breaking.py           ← срочные новости
├── bot.py / daemon.py    ← нажатия и заявки / расписание + long-poll
├── web.py, newsfeed.py, webpage.py  ← страница: HTTP и доступ, данные, HTML
└── cli.py                ← аргументы командной строки
tests/                    ← смоук-тесты, сеть не трогают
```

**Четыре нити в демоне:** long-poll `getUpdates`; `scheduler` (раз в минуту
смотрит, не пора ли собрать или отправить); `worker` (тяжёлое по одной задаче);
`web` (HTTP-сервер страницы).

**Страница и Telegram — одни и те же данные.** Лента строится из таблицы `sent`,
куда вместе с новостью пишется и сама карточка, поэтому ничего не
пересчитывается. Отправленный выпуск целиком лежит в `issues`, а в кнопке едет
только его номер (в `callback_data` всего 64 байта); нажатие раздела переписывает
то же сообщение, поэтому чат не растёт от навигации.

**Поиск по ленте — FTS5.** Над историей стоит полнотекстовый индекс
(`sent_fts`), который наполняют триггеры: писать в `sent` можно откуда угодно,
индекс не отстанет. Падежи даёт не индекс, а запрос — слово режется до основы и
ищется префиксом, поэтому «Иране» находит «Иран». Индекс собирается сам при
первом запуске новой версии; если FTS5 в сборке SQLite нет, поиск идёт перебором
по истории — медленнее, но так же.

**Данные:** `digest.db` (SQLite: материалы, история, реакции, подписчики,
здоровье источников, выпуски), `profiles.json` (ваши разделы), `digest.log`
(ротация 3×2 МБ), `env` (секреты, права 600) — всё в `~/.newsdigest/`.

**Тесты:** `python3 -m unittest discover -s tests` — сеть и Telegram не трогаются.

## 📞 Частые вопросы

**Куда делись команды?** Их нет ни в Telegram, ни на странице. Всё управление на
VPS. Кнопки под выпусками работают как работали, а «⭐ Мои темы» позволяет
подписчику выбрать, какие разделы идут первыми.

**Можно закрыть чат, чтобы туда нельзя было писать?** Со стороны Telegram — нет,
окно ввода не убирается. Можно сделать так, чтобы бот не отвечал:
`ND_CHAT_REPLY=off` (кнопки работают) или `ND_LISTEN=0` (не читает чат вовсе).

**Можно не открывать Telegram?** Для чтения — да, на странице есть вся история,
поиск и закладки. В чат выпуски при этом продолжают приходить.

**Почему источники англоязычные?** Новость берётся там, где она достовернее.
Карточка приходит на языке выпуска, остальное переводится (`ND_TRANSLATE=0`
выключает). Свои русские источники добавляются в `profiles.json`.

**Обновление сломает базу?** Нет: история переезжает на новый формат на месте.

**На странице пусто, хотя выпуски приходят.** Лента строится из истории
отправленного — её наполнит первый выпуск после обновления.

**Страница видна из интернета — это безопасно?** Новости открыты нарочно, всё
служебное закрыто паролем и гостю по сети не уходит. Но HTTP не шифрован: не
вводите пароль по чужому Wi-Fi. Строже — `ND_WEB_HOST=127.0.0.1` + ssh-туннель.

**Мой ключ может утечь к модели или в issue?** Нет: всё, что уходит к модели
и в лог, проходит через `newsdigest/redact.py` — ключи, пароли и ссылки с
токенами вырезаются до отправки. Перед публикацией логов прогоните их через
`python3 digest.py scrub`. Подробности — раздел «🔒 Секреты».

**Как экспортировать новости?**
`sqlite3 ~/.newsdigest/digest.db "SELECT * FROM sent WHERE sent_at > '2026-01-01';"`
